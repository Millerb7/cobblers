# EXP-068: the eighth starter, Misdreavus -> Mismagius -> Flutter Mane

**Status: NOT RUN. BUILT, NOT OBSERVED IN GAME (2026-10-08).** Everything below is from code and the 1.8.0 jar. Valid
JSON is the most that has been shown.

## Objective

Show in a running server that the eighth starter works as decided (the owner, 2026-10-08: "the starter's own tagged
Misdreavus at 5 (330), a tagged Mismagius at 30 (430), and Flutter Mane at 45"; only the starter line converts):

1. the 30 step turns the starter Misdreavus into the tagged Mismagius form (`cobblers_starter_1` -> `_2`), offered;
2. the 45 step turns that Mismagius into Flutter Mane, a species the jar does not relate to it, and what carries over;
3. Flutter Mane renders as the placeholder doll until the AllTheMons models ship (ADR-006);
4. a wild Mismagius (and a wild Misdreavus) never converts.

## Success criteria

Each step passes or fails on its own.

- Step 1 rests on the same mechanism as the Cosmog line's 30 step (a species change carrying `aspect=` into a form of
  the new species), which is EXP-049's; if that fails, every two-species line fails with it.
- Step 2 decides whether the line stands. It is the first evolution into an unrelated species anyone has run here.
  Pass: the Pokemon is Flutter Mane (570, Ghost/Fairy, Protosynthesis) at the same level, with the same IVs, EVs,
  nature, shininess and original trainer, its moves kept, and no `cobblers_starter_*` aspect left.
- Step 3 is expected, not a failure: the model is not delivered. It fails only if the doll breaks something beyond
  looks (a client crash, a battle that will not start).
- Step 4 fails if any wild-shaped Misdreavus or Mismagius reaches Flutter Mane by any route.

## Results

Not run.

What was checked without a game (2026-10-08), in `Cobblemon-fabric-1.8.0+1.21.1.jar` (snapshot 2026-10-05):

- `Evolution.evolutionMethod` clones the Pokemon, calls `getResult().apply(pokemon)`, then reads
  `getLearnableMoves()`.
- `Pokemon.setSpecies` writes one field (`species`), rebuilds the species features, clears the evolution
  controller, then calls `updateAspects`, `updateForm`, `checkGender`, `updateHP(float)` and `attemptAbilityUpdate`
  and sends a `SpeciesUpdatePacket`. It writes no level, IV, EV, nature, shiny or OT field; the bodies of the
  methods it calls were not read.
- `FormData.getEvolutions` returns the form's own set or an empty one, never the species'.
- The jar's species files: Misdreavus evolves to Mismagius by Dusk Stone only; Mismagius has no evolution; Flutter
  Mane has none and no `preEvolution`, `implemented` unset (off) in the bare jar, labels `gen9, paradox`.
  COBBLEVERSE-DP-v31 sets it `implemented: true`; Mega Showdown 1.0.2 has no Misdreavus, Mismagius or Flutter Mane
  data.
- `python tools/mythical_starters.py measure`: 20/35 against the gym leaders, field 15-20 (21/35 with Moonblast and
  Power Gem in the pool, which were left out).
- `python tools/mythical_starters_audit.py` and `python tools/oak_starter_audit.py --compile`: no fault.
