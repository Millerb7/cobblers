# data/gym_arenas/<gym>.json — schema `gym_arena/1`

One file per gym (`gym1.json` … `gym8.json`), read by `tools/gym_arenas.py`. A theme is pure data: nothing in
the tool is per gym, and an author never edits the tool. `survey.json` beside these files is generated
(`python tools/gym_arenas.py survey --write`) and is where an author starts: the route end, the lot, the ground,
the water, the carved spaces in data, and how high a shell may reach. The design rules and the leaders' measured
sizes are in `docs/world-building/GYM_ARENAS.md`; `data/gym_arena_sizes.json` is generated by
`tools/pokemon_sizes.py`.

Run `python tools/gym_arenas.py check --gym gymN` until it prints no `PROBLEM`. Every coordinate is absolute
(x, y, z), every box is `[x0, y0, z0, x1, y1, z1]` inclusive.

## Fields

| Field | Meaning |
|---|---|
| `schema`, `id`, `gym` | `"gym_arena/1"`, the file stem, the gym id (`gym1`; the building is `data/gym_buildings/<gym>.json`, or Misty's template for `gym2`) |
| `status`, `name`, `reading` | what is proven, the arena's name, and why it reads as this leader's and no other's |
| `leader.id`, `leader.seat` | the upstream trainer id (`kanto_brock`) and THE seat: the spawner, flush in the dais top. **This is the one source of the leader's seat** once the file exists (`gym_arenas.leader_seats()`); the building's `leader.spawner` becomes where the move starts |
| `spawn_free_zone` | the id in `data/spawn_suppression.json` `spawn_free_zones`; the arena's x/z must lie inside it (extend it on the 8-block grid if not) |
| `floor_y` | the y of the floor's top course; a player stands at `floor_y + 1` |
| `bounds` | every write inside it, or in a `through_building` box |
| `through_building[]` | `{box, why}`: where the arena may write inside or just under the building (the descent). Writes in the building's bounds anywhere else fail |
| `entry.route_end` | the cell where the puzzle route ends today (one over the building's spawner): the walk starts here |
| `entry.floor` | the first arena floor cell the player reaches; must be farther from the leader than forceBattleMaxDistance + 1 |
| `battle.trainer_pokemon`, `battle.player_pokemon`, `battle.player_stand` | Cobblemon Battle Positions blocks, at `floor_y - 1` under a full floor block |
| `battle.trainer_stand` | at `seat.y - 1`, under a full dais block, two open cells over it |
| `challenge_spawner` | ONLY for a leader outside `single_leader.rollout`: `{old_at, old_restore: {floor, under}}`, the Challenge spawner the trainers cycle set at the old seat; move `data/challenge_mode.json bosses.<id>.spawner.at` into the arena in the same change |
| `old_seat_restore` | `{floor, under}`; required only for a template seat (gym 2). For a building it is derived from the building's own model and, if given, must agree |
| `palette` | `{name: block state}`; a part names `"$name"` or a literal state |
| `blocks` | every block name the parts may write (the markers, spawner and redstone are added by the tool). A healing machine is refused |
| `parts[]` | the ops below, in order |
| `probes[]` | `{what, at, block}`: extra read-backs for the world verify and `data/world_probes.json` |

## Ops (`parts[]`)

Every op takes an optional `why`, emitted as a comment.

| op | fields | does |
|---|---|---|
| `shell` | `box`, `thickness`, `block` | the six faces `thickness` deep, then the inside carved. Build the arena from this: a natural cave can open into rock, never into a shell |
| `carve` | `box` | fill with air |
| `fill` | `box`, `block`, `mode?` (`hollow`, `outline`, `keep`) | a vanilla fill |
| `setblock` | `pos`, `block` | one block |
| `scatter` | `positions`, `block` | one block at each |
| `repeat` | `step [dx,dy,dz]`, `count`, `parts` | the nested parts `count` times, each shifted `k * step`: colonnades, ribs, bays |
| `newel_stair` | `ring [x0,z0,x1,z1]`, `top_y`, `bottom_y`, `start [x,z]`, `turn` (`cw`/`ccw`), `tread`, `landing`, `newel`, `under?`, `wall?`, `wall_to_y?`, `headroom?` | a stair winding down round a solid newel: one down per straight cell, corners are landings, so it is walked both ways; headroom carved over every tread; the ring filled solid first, so nothing between treads is left as rock |
| `straight_stair` | `from`, `dir`, `steps`, `width?`, `tread`, `under`, `headroom?` | a straight stair `steps` down in `dir` |

The tool never writes the seat or the cell under it in the build function (a fill over them is split round
them), so re-running the arena never takes the spawner away. The seat function (`<gym>_seat`) is the only writer
there.

## What the tool emits (`cobblers_gym_arenas`, world-local)

| Function | Run by | Does |
|---|---|---|
| `cobblers:gym_arenas/<gym>` | R16GA | the arena, the four Battle Positions blocks |
| `cobblers:gym_arenas/<gym>_seat` | R16G (after the buildings) and R16GA | only once the arena stands (its trainer Pokemon block): the move, spawner into the dais and the old cell back to its floor, never with a player within reach of either seat; and a spawner at the seat if neither cell has one |
| `cobblers:gym_arenas/<gym>_old_leader` | R16GA | a `tools/chunk_look.py` sweep: the leader's two ids killed inside the building's bounds, never in a battle |
| `cobblers:gym_arenas/verify` | by hand in game | one red line per probe that fails |

R16GA ends with the `gym_arenas` check (`gym_arenas.verify`), which reads every probe back over RCON.
