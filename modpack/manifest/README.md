# modpack/manifest/

Two JSON files describe the pack. Both are plain data; `tools/pack_manifest.py`
reads and (for the base) writes them.

## base-cobbleverse-1.7.42.json

Generated by `python tools/pack_manifest.py generate` from
`base-pack/inventory/mod_inventory.json` + `pack_hashes.csv`, plus hashes of a
local copy of the jars and a Modrinth hash lookup. Do not hand-edit; regenerate.

- `schema`: `cobblers.base-manifest/1`
- `base`: the Cobbleverse release this describes (Modrinth project `Jkb29YJU`, version `1.7.42`, mrpack version `4SKGla61`).
- `target`: Minecraft / loader / Java / Cobblemon version of the **base** (Cobblemon 1.7.3).
- `sources`: where the data came from, how many files were hashed locally, and any sha256 mismatches between the local files and `pack_hashes.csv` (should be empty).
- `resolution`: how the Modrinth lookup went (`method`, `resolved`, `unresolved` paths).
- `files[]`: one record per jar/zip:
  - `path` (relative to the pack root), `kind` (`mod` / `resourcepack` / `datapack` / `shaderpack`), `filename`, `size`
  - `sha256` (from the tracked CSV), `sha1` and `sha512` (computed locally; `null` when generated without the files)
  - `side`: `client` (never on the server), `both`, or `server`. From `environment` in `fabric.mod.json`; resource packs and shader packs are always `client`.
  - for mods: `mod_id`, `name`, `version`, `classification`, `disabled`, `depends_cobblemon`, `cobblemon_1_8_status`, `notes` (copied from the inventory)
  - `source`: `{"type": "modrinth", project_id, version_id, version_number, date_published, url, filename}` or `{"type": "unresolved"}` (Cobbleverse-custom files; must be copied from a local install).

## overlay.json

Hand-written. Our changes on top of the base.

- `target`: what we are building for (`cobblemon: 1.8.0`).
- `replace[]`: `mod_id`, `from_version` -> `to_version`, `to_file`, `modrinth {slug, project_id, version_id, url, filename, size, dependencies}`, `sha512`, `sha1`, `verification`, `reason`. Run `python tools/pack_manifest.py resolve-overlay` to fill the Modrinth fields from `slug` + `to_version`; anything it cannot find stays `"verification": "unverified"`.
- `remove[]`: `mod_id`, optional `file` (pins the removal to one jar when two share a mod id), `reason`.
- `add[]`: new files not in the base: `mod_id`, `kind`, `version`, `side`, `modrinth {slug, ...}` or hashes, `reason`. Empty today.
- `server_exclude[]`: mod ids that must not be installed on the dedicated server (every jar with that id is `side: client`; 33 ids). `server_exclude_ambiguous[]` lists ids shared by a client jar and a non-client jar (today only `particular`: the `.disabled` original vs. Particular Reforged) - those are decided per file, not per id.
- `needs_functional_test[]`: mods that load under Cobblemon 1.8 but whose behaviour is unverified, each with a reason.

`plan` = base `files` minus `remove`, with `replace` swapped in, plus `add`;
`--side server` then drops everything with `side: client`.

## cache/

Trimmed Modrinth API responses used by the last `generate` / `resolve-overlay`
(version ids, file names, URLs, hashes; changelogs stripped). Regenerable;
kept so the manifest can be audited offline.
