- **Runtime:** Minecraft 1.21.1, Fabric Loader 0.19.5, Cobblemon 1.8.0+1.21.1, and Java 21; the latest live log reached `Done (2.659s)`. Trainers are rctmod 0.19.0-beta on rctapi **0.16.1-beta**, pinned in `modpack/manifest/overlay.json` over Cobbleverse's 0.16.0 because 0.16.0 softlocks a battle when both sides faint at once (rctapi #132; Brock froze on staging 2026-09-24, `docs/research/notes/battle-freeze-double-ko.md`). Installed on the server; the fix is not yet reproduced in game.
- **Never switch a placed Habitat Block's style with `data merge`** (staging, 2026-09-26). Cobblemon 1.8.0's `HabitatBlockEntity` builds its spawn details once, on its first tick (`initialized` flag, not saved), and the activated style (`SpawningStyle: "cobblemon:activated"`, keys `Chance`, `Trigger`, `CancelRange`, `SpawnRange`, `MaxSpawns`, `MaxSpawnsPerActivation`) keeps its spawner in a lateinit field that only that step fills. `tools/habitat_blocks.py`'s setblock-then-merge pattern hands an already-initialised block a fresh activated style with no spawner: its tick throws, and so does every player spawning pass that reaches it. A block the owner configured by hand in the editor works (a Flamigo flock, 2026-09-26). What works by command (staging, 2026-09-26, 158 blocks, no error): set the position to another block first (re-placing a habitat block keeps its old, initialised entity), then one setblock carrying the whole NBT, including `PhaseOrder` (read with valueOf, not defaulted: leaving it out makes the setblock fail half-loaded). `tools/habitat_blocks.py` writes activated blocks that way. Neruina froze the block, then kicked the player, and wrote `neruina$errored` into that player's saved data, which silently stopped all Pokemon spawning around that player across restarts until the key was removed from the offline player file.
- **Cobblemon's spawn command inside a function: contradicted 2026-09-26** (EXP-042: `spawnpokemonat` spawned from a function run over RCON and from the tick loop; the earlier context is unrecorded). Recorded 2026-09-25 (staging): `spawnpokemonat` from the console spawns, the same line in a datapack function spawns nothing, and vanilla `summon cobblemon:pokemon` is refused even with a full Pokemon compound. A Pokemon the campaign places is summoned over RCON by `tools/reapply.py` (its `cmd` action), never by a pack.
- **rctmod never refuses a rematch with a placed trainer (standing limitation).** A trainer placed with `summon_persistent` (every trainer we or a gym place) skips rctmod's "already beaten by this player" check entirely: `TrainerMob.couldBattleAgainst` returns true for a persistent trainer before it looks (rctmod 0.19.0-beta bytecode; the owner re-battled a persistent Brock straight after beating him, no restart, 2026-09-24). For the others the check (`winsAndDefeats` against `maxTrainerDefeats`) lives only in the loaded entity and is never saved, so a restart or chunk unload forgets it (the owner beat Channeler Hope twice across a restart). What rctmod does persist is the player's own defeat count and series progress, which gate loot conditions and requirements, not rematches. Our trainers are held off by `tools/route_trainers.py`'s cycle: a player tag mirrored from their own defeat field, and a short trainer `Cooldown` while only players who beat it are near. Design against rctmod as if it forgets every win.
- **Seed:** retained in the live `level.dat`, deliberately uncommitted, and identified only by SHA-256 `48202407c92bc5d07cd215b93f631b384a5f7dde58e993e7bc9f7365e03563f3`.
