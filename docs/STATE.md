- **Never switch a placed Habitat Block's style with `data merge`.** Cobblemon 1.8.0's `HabitatBlockEntity` builds its spawn details once, on its first tick (`initialized` flag, not saved), and the activated style (`SpawningStyle: "cobblemon:activated"`, keys `Chance`, `Trigger`, `CancelRange`, `SpawnRange`, `MaxSpawns`, `MaxSpawnsPerActivation`) keeps its spawner in a lateinit field only that step fills; a setblock-then-merge hands an initialised block an activated style with no spawner, and its tick throws, as does every player spawning pass that reaches it. What works by command (158 blocks, no error): set the position to another block first (re-placing a habitat block keeps its old, initialised entity), then one setblock carrying the whole NBT, including `PhaseOrder` (read with valueOf, not defaulted: leaving it out makes the setblock fail half-loaded). `tools/habitat_blocks.py` writes activated blocks that way. A block configured by hand in the editor works. Neruina freezes a throwing block, kicks the player and writes `neruina$errored` into that player's saved data, which silently stops all Pokemon spawning round that player across restarts until the key is removed from the offline player file.
- **Cobblemon's spawn command in a function:** `spawnpokemonat` in a plain function parsed at server start does nothing until a `/reload`; a macro line works either way (EXP-046), and after a reload it spawns from a function run over RCON and from the tick loop (EXP-042). Vanilla `summon cobblemon:pokemon` is refused even with a full Pokemon compound. The ambient keeper, the blackout rebuild and the gulch Megas' keeper spawn through macros; one-off campaign Pokemon are summoned over RCON by `tools/reapply.py` (its `cmd` action).
- **rctmod never refuses a rematch with a placed trainer (standing limitation).** A trainer placed with `summon_persistent` (every trainer we or a gym place) skips rctmod's "already beaten by this player" check: `TrainerMob.couldBattleAgainst` returns true for a persistent trainer before it looks (rctmod 0.19.0-beta bytecode; the owner re-battled a persistent Brock straight after beating him). For the others the check (`winsAndDefeats` against `maxTrainerDefeats`) lives only in the loaded entity and is never saved, so a restart or chunk unload forgets it. rctmod persists the player's own defeat count and series progress, which gate loot conditions and requirements, not rematches. Design against rctmod as if it forgets every win.
- **Our hold-off and mixed progress.** `tools/route_trainers.py`'s cycle mirrors each player's own defeat field into a tag and writes a short trainer `Cooldown` **whenever any player near the trainer has beaten it**, so a winner is never dragged into a rematch; the cost is that an unbeaten partner must start the fight themselves (`tests/test_trainer_holdoff_mixed_progress.py`, a plain test, runs the cycle in `tests/mcfunction_sim.py`; provable offline only for the 6 eye-contact trainers). It covers every placed trainer the moment two people play. **The proper fix the owner chose: per-player trainers through the scene runtime** (`tools/scenes_pack.py`'s per-player actors), gated on EXP-034 and a second account.
